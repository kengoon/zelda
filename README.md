# 🛡️ Building a 2D Zelda Clone in Python (Kivy & Kivent)

Welcome to the repository for the **Zelda Clone** 2D game development series! This project is built using **Python**, the **Kivy** framework, and the high-performance **Kivent 2D** game engine, implementing an **Entity Component System (ECS)** paradigm to handle standard RPG gameplay, physics, rendering, and custom state. 

This repository tracks the development of our Zelda-inspired RPG, starting from our foundational setup and game system declaration to advanced tilemaps, AI, and combat.

---

## 🎮 Key Tech Specs
* **Language:** Python 3.x
* **Framework:** [Kivy](https://kivy.org/) (for windowing, UI, & input)
* **Game Engine:** [Kivent 2D](http://kivent.org/) (for fast, Cython-powered ECS game loop & physics)
* **Design Pattern:** Entity Component System (ECS)
* **Aesthetics:** 16-bit Top-down pixel-art RPG 

---

## 🚀 Features (Part 1: Foundational Setup)
In this initial setup, we lay down the groundwork for the 2D engine:
* **Window & Game Loop:** Setting up the basic Kivy App and Kivent `GameView`.
* **Game Manager:** Initializing the `GameWorld` that controls everything.
* **Systems Declaration:** Setting up the game systems that handle game logic:
  * `position`: Track where game objects are.
  * `render`: Render sprites efficiently via Cython/OpenGL.
  * `input`: Map keyboard and controller signals to movements.
  * `collision`: Prepare basic 2D hitboxes.

## ⚙️ Installation & Setup

Before you start, ensure you have Python (3.7 - 3.10 is recommended for Kivent compatibility, as compiling on 3.11+ can sometimes be tricky depending on your OS) and a C compiler installed if building Kivent from source.

### 1. Clone the Repository
```bash
git clone https://github.com/YOUR_USERNAME/zelda-kivent-clone.git
cd zelda-kivent-clone
```

### 2. Create a Virtual Environment (Optional but recommended)
```bash
uv sync
```
*(Alternatively, you can manually build Kivent from their latest master or wheels depending on your platform).*

## 🧠 Behind the Scenes: Declaring Game Systems

In `main.py`, our `GameWorld` acts as the organizer. The fundamental systems we declare look like this:

```python
# Code overview
self.systems = [
    'position_system',    # Keeps track of spatial coords
    'render_system',      # Handles high-speed sprite rendering via GL
    'animation_system',   # Applies delta updates to moving entities
    'camera_system'       # Camera following & map boundaries
]
```

Entities (like our Player or Link-style hero) will be generated by combining these modules (e.g. `Position` + `Render` + `Input` = Controlled Character).
